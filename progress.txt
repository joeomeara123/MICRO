## 2026-01-11 | Integration Architecture Designed

### Summary
- Designed complete OAuth integration architecture
- Answered key questions about how users connect accounts
- Created security model for token storage

### Key Decisions
1. **Build OAuth directly** - Not using Nango/Merge, full control over each integration
2. **Gmail with Google Sign-In** - Single OAuth flow grants both auth + Gmail access
3. **Tokens server-side only** - Encrypted in Supabase, never touch mobile app
4. **API calls via Edge Functions** - Automatic token refresh, security

### User Flow
```
1. Sign in with Google → Creates account + Gmail access
2. Settings → Connected Apps → Connect Notion/Slack
3. Each service OAuth opens in browser → Authorize → Token stored
4. App pulls personalized data from connected services
```

### Database Schema
- `users` - Core identity
- `connected_apps` - Which services connected (provider, status, scopes)
- `oauth_tokens` - Encrypted tokens (RLS: client cannot read)

### Services Layer Architecture
```
services/
├── auth/google-auth.ts       # Google OAuth + Gmail scopes
├── integrations/             # OAuth flows per provider
│   ├── base-integration.ts   # Abstract pattern
│   ├── notion.ts
│   └── slack.ts
└── api/                      # API clients
    ├── notion-client.ts
    ├── gmail-client.ts
    └── slack-client.ts
```

### Security Pattern
- Tokens encrypted with pgcrypto (AES-256)
- Encryption key in Supabase Vault
- All API calls proxy through Edge Functions
- Client never sees raw tokens

### Architecture Patterns

**Auth Context Pattern**
```typescript
// AuthContext provides: user, session, isLoading, isAuthenticated, signIn, signOut
// Uses Supabase onAuthStateChange for reactive updates
// Loading state true until initial session check completes
```

**Google OAuth with Gmail Scopes**
```typescript
const GOOGLE_SCOPES = [
  'openid', 'email', 'profile',  // Auth
  'gmail.readonly', 'gmail.send', 'gmail.modify'  // Gmail access
];
// Requests offline access for refresh token
// Signs in to Supabase with signInWithIdToken
```

**Protected Route Logic**
```
Auth State Check:
├── isLoading → Show loading spinner
├── !isAuthenticated → Redirect to /sign-in
└── isAuthenticated:
    ├── onboarding_complete === 'true' → /(tabs)
    └── else → /onboarding
```

### Key Implementation Decisions
1. **Single hook pattern** - `useAuth()` wraps context for convenience
2. **State-driven navigation** - Auth state changes trigger routes, not manual redirects
3. **Confirmation dialog** - Sign out requires user confirmation with haptic feedback
4. **Onboarding flag** - AsyncStorage `onboarding_complete` determines post-login destination
